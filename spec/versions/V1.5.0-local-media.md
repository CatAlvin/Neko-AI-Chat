# V1.5.0 · 媒体保存与本机内容理解

版本号: V1.5.0  
目标: 保存图片、语音、文件和视频，并按开关提取可供回复使用的内容。  
## 行为要求

1. 按 OneBot Array 分段保存附件顺序、类型、文件名、大小、来源标识和原始元数据。
2. 白名单媒体默认落盘，支持全局与类型开关、单文件上限；初始上限 50 MB。保存失败仍记录原因。
3. 语音优先经 NapCat `get_record` 转换后保存；图片与文件按本地路径、下载地址及相应 OneBot 查询结果处理。
4. 本机理解独立于保存开关。图片使用 Ollama 视觉模型，语音使用 faster-whisper，PDF、DOCX 和常见文本文件只读提取。
5. MIME 与扩展名共同参与路由，作为普通文件上传的图片或音频仍可识别。视频保存不等于本机已具备视频理解。
6. 每附件分别保存识别状态、识别模型、文本和错误码。正文与识别结果共同进入当前 user 内容，不丢掉用户要求。

## 数据与控制

附件存于数据目录 `media/YYYY/MM/DD/<消息 ID>/`，记录本地相对路径及哈希。临时链接及时获取；下载失败可定位但不伪造成功。管理员信任联系人表示允许处理其资料，不表示允许执行附件里的程序、宏或指令。

默认理解关闭；Whisper 首次下载需显式允许。模型不可用、格式不支持、文本为空应分别显示，不统称“读不到文件”。媒体没有取得内容时不能猜测图片、语音或文档含义。

## 实施与验收

先接附件落库和下载，再做本地提取、提示组装及会话预览。覆盖图片、语音、PDF、普通文本、伪扩展名、超限、过期链接、模型未安装、纯媒体及图文混合消息。

保存成功与识别成功分开验收；必须检查实际模型请求中含有提取证据和用户问题。

## 回退

关闭理解或类型保存开关，保留既有附件元数据及原文件。云端原生媒体处理由 V1.12.0 引入，不在本版默认上传。

实现入口：`backend/app/services/media.py`、`backend/app/services/media_understanding.py`。验证入口：`test_media_messages.py`、`test_media_understanding.py`。
