# V1.1.0 · QQ 官方回调与真实验收

版本号: V1.1.0  
目标: 接入 QQ 官方 Bot，正确完成回调地址验证、消息验签、持久化入站及单联系人验收。  
## 问题与目标

公网入口返回 HTTP 200 只说明请求得到响应，不能证明平台签名校验通过。回调保存失败必须区分地址、服务不可用、凭据和挑战响应错误。

## 功能契约

- 为平台验证请求返回规定的挑战内容及签名；普通事件按官方验签流程验证原始请求体。
- 回调路径固定为 `/api/v1/connectors/qq/webhook`。本机端口与公网 HTTPS 映射分别检查。
- 事件先提交 `ConnectorEvent`，再返回 ACK；模型处理不占用平台回调等待窗口。
- 收件箱以稳定事件键去重；处理中断可恢复，但恢复入站不意味着补发历史出站。
- 发送使用官方账号凭据及目标身份，保存平台返回的消息 ID；不得把个人 QQ 托管身份与 Bot 身份混为一谈。

## 开发拆分

先做挑战响应与验签测试，再实现持久化收件箱、后台处理及重启恢复；最后接官方出站和验收统计。诊断区必须同时展示事件接收、处理状态和发送结果。

## 验收要求

有效签名通过，篡改正文、错误签名及缺失凭据被明确拒绝；同一事件多次投递只处理一次。验证 401、404、503 与业务错误的展示，不能统一显示“服务正常”。

真实验收要求同一测试联系人的 200 条唯一入站走完端到端流程，重复回复、错收件人、急停违规均为 0，完成急停演练且收件箱清零。NapCat 的测试记录不计入官方 Bot 的 200 条。

## 边界与回退

公网服务不可达或验签错误时先修复入口，不放宽验证。停用账号必须取消其待发消息；保留收件箱和审计用于定位。后续实验连接器独立于官方通道验收。

实现入口：`backend/app/channels/qq_webhook.py`、`backend/app/channels/qq.py`、`backend/app/api/connectors.py`。验证入口：`test_qq_webhook.py`、`test_qq_acceptance.py`、`test_failure_recovery.py`。
