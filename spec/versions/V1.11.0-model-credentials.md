# V1.11.0 · 凭据稳定性与分层模型兜底

版本号: V1.11.0  
目标: 解决云模型间歇失败及 Windows 权限上下文引起的凭据不可解密，增加 Qwen 云端和本地兜底。  
## 凭据与诊断

将本机保存机制收敛为安装级密钥加密，解除普通用户与管理员终端上下文对新凭据的绑定。旧 DPAPI 凭据能解密时迁移，不能解密时逐项提示重新录入；单项 QQ 凭据失败不能阻断可用的 DeepSeek。

连接测试必须区分鉴权、模型名、地址、网络、超时和协议错误。同一 Token 重填后恢复只是现象，不能把重填作为永久解决方式。模型配置保存、读取和测试使用一致的凭据引用。

## 模型能力

支持 DeepSeek、OpenAI 兼容接口、Qwen Cloud 和 Ollama。Qwen 本地模板通过 Ollama 的 `qwen3.5:9b` 提供，保留其他 Ollama 模型作为后备。模板默认禁用，需模型或凭据就绪后启用。

单个 Provider 最多重试一次，再尝试下一个启用项。全部失败停止本次发送并记录风险。短期失败聚集保留告警，不把整个系统永久切到静默；下一条消息可以重新尝试恢复的 Provider。

## 可维护性边界

Provider 管协议与模型响应，Gateway 管重试、回退及使用统计；业务管线不直接拼厂商请求。显示成功的真实模型，不能把配置首选当作实际结果。

停用一个云模型不自动意味着纯本地，其他云 Provider、媒体上传和联网工具均要纳入判断。现有“本地处理”路由是优先级调整；严格纯本地需要关闭所有云调用入口。

## 验收与回退

覆盖安装级加密重读、旧凭据迁移、单个损坏凭据、错误模型、超时、全部失败、恢复后重新成功及本地模型不存在。迁移前备份原密文和密钥；不得以清空凭据表修复问题。

实现入口：`core/security.py`、`llm/providers.py`、`llm/gateway.py`、`services/provider_health.py`。验证入口：`test_credentials.py`、`test_provider_protocols.py`、`test_llm_failure.py`。
