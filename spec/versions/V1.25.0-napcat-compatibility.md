# V1.25.0 · NapCat 与 QQNT 兼容升级

版本号: V1.25.0  
目标: 修复 QQ 自动更新后 NapCat 底层适配失效，升级官方 Shell 包并保全账号网络配置。  
## 本版兼容基线

本次升级目标为 NapCat `4.18.19 → 4.18.28`，适配 QQNT `9.9.35-52892-x64`。这是本次环境的版本组合，不表示此后任意 QQ 更新都已兼容，也不把此版本写成永久的“最新版”。

官方来源：[v4.18.28 Release](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.28)。Shell 包 SHA-256：`bcdd8bdb9e44bd0cf6a90908e572141787fd9e98cb8d8eecc5adf25bbdcabb94`。

## 更新流程

1. 核对实际 QQ 版本目录、NapCat Core、启动方式与正在运行的进程，不能读取根目录 package.json 的占位版本作结论。
2. 从官方发布信息确认稳定版及兼容表，下载到临时目录并核验哈希。
3. 确认相关 QQ/NapCat 已退出，完整保留旧安装目录，再部署新程序。
4. 迁回账号、HTTP Server/Client、Token 等配置及所需本地数据库；升级前后比较配置文件哈希。
5. 验证 Core 版本、QQNT 加载、WebUI，再由用户完成登录并验证协议适配器与 OneBot 服务。

## 验收层级

文件验证、启动验证、账号登录、Packet 后端初始化和真实收发是不同层级。出现二维码说明需用户登录，不能据此宣布 Packet 与文件收发已完成验收。启动日志未出现不支持错误也不能代替登录后的接口验证。

当前升级记录包含 9 个配置文件一致性检查及启动验证；真实账号收发按连接器验收另行记录。升级过程不主动给联系人发测试内容。

## 回退与运维

旧目录保存在 `<local-backup-directory>`。回退前停止新版本并保存新产生的数据；如果 QQ 已不兼容旧 NapCat，单独恢复程序目录不能保证恢复服务。

不安装自启、托盘或崩溃拉起。以后 QQ 升级需重新核对兼容组合，不能依靠重复登录或修改版本显示字符串修复底层接口。

关联入口：`<NapCat-install-directory>`、`backend/app/services/system_health.py`、`backend/app/channels/experimental.py`。验收按安装文件、配置哈希、启动日志和登录后 API 分项记录。
