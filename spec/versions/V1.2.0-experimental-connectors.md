# V1.2.0 · NapCat 与 AutoWx 托管策略

版本号: V1.2.0  
目标: 增加本机 NapCat OneBot 11 接入和 AutoWx 入站草稿能力，支持分步骤完成配置。  
## 配置流程

NapCat 登录 QQ 后，创建本机 HTTP Server 与 HTTP Client。Server 默认 `127.0.0.1:3001`，消息格式 Array；Client 向 `/api/v1/connectors/napcat/events` 上报。Neko 保存相同的访问 Token 和 API 地址，再进行 SHADOW 验证。

## 行为要求

1. Neko 兼容 NapCat 原生 `x-signature` 与 Bearer Token 鉴权；错误、缺失、不同账号凭据必须拒绝。
2. 保存配置、API 可访问、账号实际在线、已经收到真实入站分别展示，不以 READY 代替 ONLINE。
3. 文本、消息段、通知事件先规范化。输入状态等非聊天事件不能触发 AI 回复。
4. 409 配置或状态冲突、401 鉴权失败、503 通道不可用应有可定位原因。
5. SHADOW 全链路生成并保存，禁止调用真实发送接口。LIVE 沿用确定性策略及最终复检。
6. AutoWx 只接收本机鉴权入站并生成草稿，不提供自动发送实现。

## 数据与边界

`Account` 明确记录平台、连接器类型、启用状态和实验属性。NapCat 的本地地址、Token 及实际登录账号必须能关联。HTTP Server 只绑定回环地址；默认实验策略关闭。

## 实施与验收

依次完成凭据保存、鉴权、事件适配、状态展示、白名单 SHADOW、受限 LIVE。覆盖同 Token 不同传输形式、私聊与群聊、非消息通知、重复回报、禁用通道。

不能以 NapCat 控制台“接收”证明 Neko 已入库，也不能以 Neko“已生成”证明 QQ 已收到。验收须检查消息、审计和平台回执三处。

## 回退

可独立停用实验连接器，不影响数据库或其他平台配置。账号切换与隔离在 V1.6.0 继续收敛。

实现入口：`backend/app/channels/experimental.py`、`backend/app/api/connectors.py`。验证入口：`test_experimental_connectors.py`、`test_channel_shutdown.py`。
