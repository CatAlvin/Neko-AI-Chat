# V1.17.0 · 长文档完整交付与自然回复

版本号: V1.17.0  
目标: 长篇分析自动以 PDF/TXT 交付，避免截断、文件正文回流聊天及固定 Emoji 签名。  
## 触发与生成

用户明确要求报告、长篇分析、完整教程、PDF/TXT 时，提前进入长文档任务，不能先按聊天长度截断再包装。一般 NapCat 回复超过安全长度时，也应转为文件交付；默认阈值 1200 字，可配置 500–4000。

长文档提高输出预算，云端默认 4096 tokens、本地默认 2048 tokens。模型因长度停止时继续生成并去除重叠，总计最多四段；仍未完成则记录失败，不发送残缺报告。

## 文件与正文

默认生成 PDF，明确要求 TXT 时使用 UTF-8 TXT。聊天只保留自然的完成说明与附件，不摘录、预览或重复文件正文。完整文本存入附件分析字段，后续引用文件可直接取用。

长文档使用完整正文进行敏感内容与未经授权承诺检查；重要联系人限制不能提前把文档裁成 400 字。发送失败保留文件及原因，禁止据此声称交付完成。

## 人格与语言

统一简体中文。Kimi 提示中禁止固定签名、机械结尾和连续 Emoji，允许根据语境偶尔使用一个表情；本地 Guard 保留必要语言归一化。角色风格不能压过事实、用户明确要求和工具结果。

## 验收

覆盖正常结束、一次和多次续写、重复段落、达到续写上限、中文 PDF、TXT 编码、重要联系人长文以及用户下一条普通问题。后续普通聊天不能携带并复述上次 PDF 正文。

## 实施与回退

先分离内容生成与交付格式，再处理续写、文件生成和短回执，最后调整风格。文档生成失败时说明失败原因，不将截断版本当作成功兜底。

实现入口：`long_form.py`、`text_overflow.py`、`provider_style.py`、`core/language.py`；验证入口：`test_long_form.py`、`test_provider_style.py`、`test_reference_context.py`。
