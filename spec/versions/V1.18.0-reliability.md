# V1.18.0 · 可靠性中心与 Windows 运行管理

版本号: V1.18.0  
目标: 集中诊断配置、显示模型降级、追踪消息投递并提供关系提醒；评估同权限常驻运行。  
## 配置与降级

向导检查 NapCat 实际登录账号、Token、HTTP 服务、数据库迁移、模型和媒体依赖。切换账号后指出具体缺项，提供可执行的修复提示。

降级中心展示配置首选、实际成功模型、最近成功、失败原因及本地/云端属性。重试按钮只测试连接；连接成功不宣称聊天和文件上传均成功。

## 待发箱

每条消息分阶段记录生成、排队、发送开始和平台确认，关联尝试次数、外部消息 ID 及错误。只有 FAILED、纯文本、且能证明尚未调用通道的白名单失败类型允许重试。

只要发送已经开始，超时或响应丢失均按结果不确定处理，禁止自动补发；附件和部分发送不整体重试。重试前重新执行当前账号与权限检查。

## 关系助手

生日、长期未回复、待处理承诺和重要话题形成提醒。默认在本机后台提醒管理员，不擅自向联系人发起聊天。提醒与联系人委托通知属于不同功能。

## 运行管理阶段方案

本阶段提出当前用户计划任务、托盘和崩溃拉起，目标是统一权限并便于启动。安装、退出、重复启动与监督状态必须可验证，PowerShell 中文脚本需兼容 Windows PowerShell 5.1 编码。

该运行管理方案后由 V1.24.0 完整撤回。当前交付不能继续执行本节安装动作，也不保留自动拉起入口；本版可靠性中心、待发账本和关系提醒继续有效。

## 验收与回退

覆盖缺凭据、错账号、迁移落后、模型恢复、发送前失败和发送后超时，验证“未知结果不重发”。监督方案出现跨权限或停止失效时恢复手动脚本，不能无限重启掩盖错误。

实现入口：`configuration_diagnostics.py`、`provider_health.py`、`outbox.py`、`relationship_assistant.py`；验证入口：`test_reliability_center.py`、`test_service_control.py`。
