# V1.10.0 · 未回复诊断与联系人工作区

版本号: V1.10.0  
目标: 为任意消息解释未回复原因，集中展示联系人策略、引用证据和媒体资料。  
## 诊断链路

从消息详情进入“为什么没回复”，依次查看入库、账号归属、白名单、AI 开关、时段、运行模式、模型调用、内容审核、排队和实际发送结果。尚未执行、失败、被拦截应使用不同状态；不把步骤未执行显示为通过。

模型失败显示实际尝试对象与错误类型；连接器错误保留关联事件 ID 和必要堆栈定位，修复 NameError 等代码问题时增加对应失败路径验证。不能只把风险标为已处理而忽略原因。

## 工作区要求

联系人详情集中管理白名单、AI、记忆、重要程度、风格、时段、续火、媒体保存和近期异常。任何覆盖项必须能区分“继承全局”与“联系人自定义”。

引用预览展示原消息、文件提取、语音转写或图片描述，标明来源和处理状态。媒体库按联系人、类型与时间筛选，展示文件名、预览、哈希、本地路径和分析结果。

## 账号与访问边界

所有详情从服务器按消息、会话和账号关联取数。后台诊断不能混用当前账号状态解释另一账号历史消息；原消息不因诊断而重新发送或重新调用模型。

## 验收

分别构造未入管线、关闭 AI、时段外、模型全部失败、审核拒绝和平台响应未知的消息。诊断必须给出实际阻断点，已通过环节仍保留。切账号后历史媒体来源正确，图片预览失败有占位和原因。

## 实施与回退

先组合已有审计和投递记录，补充缺失事件，再做详情页与媒体列表。展示接口异常不应影响接收与发送。实现入口：`observability.py`、`system_health.py`、`api/routes.py`、`frontend/app/page.tsx`；验证入口：`test_observability_and_account_isolation.py`、`test_system_health.py`。
