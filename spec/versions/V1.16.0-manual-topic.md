# V1.16.0 · 后台人工发送与管理员话题委托

版本号: V1.16.0  
目标: 在会话中直接发送人工消息，并让管理员指定Neko主动与某位白名单联系人聊一个话题。  
## 人工消息

实时会话增加输入区、发送状态及失败反馈。后台发送的消息标记 HUMAN，并记录平台回执；不进入普通 QQ 客户端发言触发的人工接管等待。NapCat 自身消息回报应关联该条记录，避免二次入库或接管。

人工发送仍核对会话、账号与目标，不允许切号后沿用旧页面目标。从后台手动发送不等于解除全局急停或改为自动模式。

## 主动话题

管理员使用“找/聊聊/发起对话”命令指定目标和话题。目标必须是当前账号唯一匹配的白名单联系人，生成时使用该联系人的记忆和近期对话。

首条消息自然说明话题来自主人的建议或委托，不拼接固定“主人让我来找某某”开头。模型若遗漏来源，可整体重写一次；仍遗漏则返回失败原因。

该命令视作明确即时委托，不使用普通文本发送的六位代码流程。发送前仍执行目标、AI 开关、账号、LIVE/AUTO、急停、时段、频率与内容审核。后续对话进入普通管线，不无限主动追问。

## 模型与语法演进

话题委托优先可用的 Kimi K3，失败按启用模型链继续；管理员回执显示实际模型。本版目标与话题分隔方式由 V1.22.0 最终统一为 `-`。

## 验收与回退

验证后台人工消息不改变 HUMAN 等待、同名目标要求澄清、生成期间撤销白名单阻止发送、自然委托说明、实际模型记录和重复回报去重。功能关闭只取消待发委托，不删除已发送内容。

实现入口：`pipeline.py`、`proactive_topic.py`、`api/routes.py`；验证入口：`test_admin_commands.py`、`test_mode_semantics.py`、`test_experimental_connectors.py`。
