# V1.0.0 · 本地消息托管 MVP

版本号: V1.0.0  
目标: 在个人 Windows 电脑上完成可控的消息接收、自动回复、记录、人格与联系人记忆闭环。  
## 使用场景与范围

日常低频聊天可交给Neko处理；本人随时查看记录、暂停或接管。先以 Simulator 验证核心行为，再接真实平台。后台必须能管理联系人、群聊、模型、人格、记忆、用量、风险和发布门禁。

## 行为与边界

1. `SIMULATION` 调用模拟通道，`SHADOW` 接收并生成但不真实发送，`LIVE` 才允许进入真实出站。
2. 运行模式与发布环境分别管理。`AUTO` 允许按策略生成和发送；其余模式按各自语义收紧处理，急停直接阻断出站。
3. 私聊默认白名单准入；群聊必须获准且明确 @ 托管账号。联系人重要程度分普通、重要、仅人工。
4. LLM 只负责回复内容。白名单、急停、账号、时段、限流、接管和内容审核由代码判断，排队后再次检查。
5. 长期记忆分偏好、个人事实、关系背景、持续话题、交流习惯五类，按联系人隔离；会话摘要独立保存。
6. 单用户后台首次设置管理员，不预置通用密码。对外账号凭据加密保存，日志不输出密钥。

## 数据与开发顺序

FastAPI 提供 API 和 WebSocket；React 后台呈现状态；SQLAlchemy/Alembic 支持本地 SQLite 与专用 MySQL。先建立账号、联系人、会话、消息、运行状态，再接策略、模型网关、摘要与后台控制。

消息至少保存方向、作者、来源 ID、正文、状态、策略原因和时间。模型结果保存 Provider、模型及 Token；异常形成可查询的审计事件和风险项。发布门禁与实际发送共用状态检查入口。

## 退出条件

- 白名单模拟消息能够完成接收、策略、生成、审核、排队、发送、记录。
- 非白名单、未获准群聊、急停、仅人工及接管期间均不能自动发送。
- 重复事件不会产生第二次回复；联系人之间不共享记忆。
- 1000 条模拟入站演练不得丢消息、重复发送或发给错误收件人。
- 云端模型、真实 QQ、MySQL 单独留存环境证据，不用模拟结果替代。

## 回退与后续

问题版本降级到 SHADOW，取消待发消息并保留入站记录。真实连接器从 V1.1.0 起接入；正式事务与记忆审核的后续调整见 V1.21.0、V1.22.0。

实现入口：`backend/app/services/pipeline.py`、`backend/app/policy/engine.py`、`backend/app/llm/gateway.py`。验证入口：`test_policy_invariants.py`、`test_pipeline_stability.py`、`test_memory_isolation.py`。
