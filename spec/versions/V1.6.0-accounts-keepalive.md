# V1.6.0 · 账号配置隔离与每日续火

版本号: V1.6.0  
目标: 方便切换至少两个 QQ 的配置，避免切号错发；联系人可独立开启每日续火。  
## 账号决策

本版采用多配置、单活账号。同一时刻只激活一个 NapCat 配置；同时双 QQ 实时托管必须另行完成实例、端口、凭据、入站归属与出站隔离，不能仅增加两个账号选项便视为完成。

每配置保存显示名称、托管 QQ、回环 API 地址和独立 Token。NapCat 的网络设置随登录 QQ 分别保存；切换后缺少 HTTP 配置须明确指出。激活前核实 OneBot 实际登录 QQ，不能把已保存配置直接当作在线事实。

## 切换契约

联系人、群聊、会话、消息、记忆和任务按账号关联。在同一发送锁内停用旧配置、取消 NapCat 待发消息、激活新配置。最终发送重新核对活动账号；生成期间切号不能导致旧请求从新账号发出。

## 续火契约

续火是独立、可关闭的联系人授权，允许未加入普通 AI 白名单的联系人接收每日一条续火，但不因此开放其入站给 AI。指定账号和北京时间 `HH:MM`，文案使用本地模板与日期，不调用模型。

调度每 30 秒检查，离线后可在当天允许时段内补一次。调用通道前持久化当日尝试；响应丢失也不能当天自动再发。仍检查 LIVE、AUTO、急停、绑定账号、时段与总量。

## 验收与回退

验证两账号相同 QQ 联系人标识不会串记忆，切号取消旧队列，登录 QQ 不匹配拒绝出站。续火覆盖关闭开关、非白名单授权、错账号、跨北京时间日期、断网与进程中断。

停用续火后不得再调度；切回旧配置应恢复其配置而非复制新账号状态。保留用户登录 QQ 的手动步骤。

实现入口：`backend/app/services/account_selection.py`、`backend/app/services/keepalive.py`、`backend/app/api/routes.py`。验证入口：`test_observability_and_account_isolation.py`、`test_experimental_connectors.py`。
