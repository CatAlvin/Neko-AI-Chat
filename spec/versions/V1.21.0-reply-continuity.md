# V1.21.0 · 管理员回复连续性与正式事务回执

版本号: V1.21.0  
目标: 解决管理员与联系人反复无回复的问题，正式事务记录后台后也应得到恰当回应。  
## 回复语义调整

正式事务不再简单终止整个聊天分支。识别到合同、申请、面试等本人事务时创建高优先级待办，关联来源消息，并在回复中明确“已在后台记录”。同一来源消息只创建一次。

Neko可以解释信息、整理材料和回应，但不能代表本人签约、付款或作强承诺。公开知识问题与正式办事意图分开识别，不能因为出现学校、公司等词就无条件阻断。

## 管理员例外范围

管理员不受普通联系人连续托管轮数导致的自动冷却，避免正常管理会话中途失联；仍受急停、账号、白名单、AI 开关、时段、敏感信息与发送限制约束。显式人工接管仍有效。

“问主人”意图在普通回答前进入代答待办流程，不能被人格回答吞掉。模型错误、媒体失败和分支提前返回都要保留明确原因。

## 诊断顺序

从最新入站 ID 查接收记录、账号与联系人，沿策略、引用/工具、模型、待办、队列到平台回执逐步定位。修复共享问题时覆盖管理员和普通联系人两类路径，不只改一个 QQ 号的特例。

## 验收

验证管理员超过普通轮数后继续回复、正式事务创建一次待办并给回执、正式承诺仍被拒绝、网络恢复后新消息可处理、媒体与文本混合不丢用户要求。失败记录不得标为 SENT。

## 实施与回退

使用独立 `formal_matter` 服务记录待办，复用回复和投递管线。新分支异常保留来源消息并报告，不通过取消全部限制解决无回复。

实现入口：`formal_matter.py`、`policy/engine.py`、`pipeline.py`；验证入口：`test_mode_semantics.py`、`test_admin_commands.py`、`test_online_tools_and_delegated_todos.py`。
