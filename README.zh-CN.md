# Neko AI Chat

**将消息接入、模型路由、联系人记忆、多模态理解和投递追踪连接起来的本地 AI 消息平台。**

[English](README.md) · [运行方法](README.md#run-locally) · [真实使用统计](docs/USAGE_REPORT.md) · [需求与设计](spec/README.md)

![Neko AI](docs/assets/cover.svg)

我主导了系统架构、主要功能逻辑和各模块实现，并在实际聊天中使用。系统基于 FastAPI、SQLAlchemy 与 Next.js，支持 Kimi、DeepSeek 和 Ollama 本地模型，提供消息托管、人工回复、联系人记忆、图片理解、语音转写、文件上下文及后台任务。

## 实际使用成果

对实际 MySQL 数据库进行只读核验后，排除模拟器记录，得到以下结果：

| 指标 | 结果 |
| :--- | :--- |
| 有消息记录的自然日 | **35 天**，2026-08-26 至 2026-09-29（北京时间） |
| QQ 渠道消息记录 | **1,157 条**，其中入站 493 条 |
| 大模型生成并标记发送成功 | **368 条**，另有 93 条模板消息 |
| 投递账本平台确认 | **193 / 195 条，98.97%** |
| 完成的媒体理解 | **118 次**：图片 84、语音 29、文件 5 |
| 留存审计中的重复事件拦截 | **116 次** |
| 自动化回归测试 | **551 项通过**，包含 1,000 条事件的策略与重放测试 |

数据在 2026-10-07 核验；统计分母、失败记录与日志覆盖范围见[使用报告](docs/USAGE_REPORT.md)。35 天表示历史上有消息记录的日期数，不是连续在线时长。

## 工程设计

消息先归档与去重，再准备记忆和媒体上下文，由模型路由生成回复；发送前重新检查当前账号、联系人策略、限流及人工接管状态，最后记录平台回执。生成、排队、发送和平台确认分别追踪，使问题可以定位到具体阶段。

![实际界面，使用虚构联系人和本地 Ollama 回复](docs/assets/conversation.jpg)

开发以需求规格为依据，使用 Codex 辅助实现与迭代（Spec 驱动的 Vibe Coding）；主要产品决策、功能逻辑和系统架构由我设计。49 份规格文件覆盖版本演进、接口契约、实现追踪和运行流程。

运行依赖 Python 3.12、Node.js 22.13+。首次启动使用本地 SQLite 和模拟模式，由使用者创建管理员账号；可按需配置 MySQL、模型提供商与 QQ 连接器。完整安装和测试步骤见[英文 README](README.md#run-locally)。
